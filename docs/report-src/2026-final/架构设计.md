## 启动
通过makefile时传入profile设定构建目标平台（架构和平台是绑定的，不能拆开）：
```
CPU：LoongArch  
平台：2K1000
硬盘：AHCI
网卡：GMAC
中断：LIOINTC
链接脚本：2K1000 专用
```
架构入口只负责处理DTB（CPU和固件传来的特殊参数）输出统一的BootInfo，然后调用公共入口
```
boot::initialize_kernel({
	.boot_cpu_hwid = hartid,
	.device_tree_paddr = k_dtb_addr,
});
```

## 构建系统
为了应对多配置编译，修改原本的大makefile，进行解耦和。
### 设计思路
makefile参数要解决这些问题
- 哪种 CPU？       ARCH=riscv / loongarch  
- 在哪个平台运行？ BOARD=qemu / visionfive2 / 2k1000  
- 要启动什么？       INITCODE_MODE=evaluation / shell

为了兼顾易用性和规范，设计了如下构建指令系统
```
make <动作> PROFILE=<完整平台画像> MODE=<启动模式>
```
常用指令
```
#比赛入口
make all 
  
# 构建  
make build PROFILE=riscv-qemu 
make build PROFILE=loongarch-qemu  
make build PROFILE=riscv-visionfive2 MODE=shell  
make build PROFILE=loongarch-2k1000 MODE=shell 
make clean
 
# QEMU  
make run PROFILE=riscv-qemu QEMU_DISK=final QEMU_MEM=8G QEMU_SMP=8
make run PROFILE=loongarch-qemu
make shell PROFILE=riscv-qemu  
make debug PROFILE=loongarch-qemu  
 
# 查询  
make help  
make profiles  
make print-config PROFILE=loongarch-2k1000 MODE=shell
```
### 实现方法
采用顶层makefile存交互式指令 + mk文件夹存具体实现/板级配置的形式实现。
#### 捕获方式
通用模块递归自动捕获（按文件夹归类）
架构专属文件、平台专属文件按配置自动捕获（按文件夹归类）
可复用硬件驱动显式加入配置文档
#### 更新方式
stamp -> 记录makefile和文件信息，makefile修改，构建参数不同也会出发重新构建
sources.list -> 源码移动，删除，新增也会重新构建
